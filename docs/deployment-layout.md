# Deployment layout

This document is the source of truth for where Komodo clones, configuration and
persistent data live. The goal is one rule per host, with no stack-specific
exceptions beyond the ones listed here.

## Host directories

```text
/home/deployer/homelab/        # developer clone (Git commits and pushes)
/opt/stacks/<stack>/           # Komodo clones (disposable, reproducible)
/opt/core/<stack>/             # persistent state for infrastructure stacks
/opt/compose/<stack>/          # persistent state for application stacks
/srv/                          # bulk data (media, Nextcloud, backups)
/mnt/media/                    # large media library
/var/lib/docker/volumes/       # named Docker volumes
```

`/etc/komodo/stacks` is **not** part of the host layout. It only exists inside
the Periphery container; host copies are leftovers and must not be used.

## Komodo stack settings

Git-managed stacks use:

```text
clone_path:      /opt/stacks/<stack>
run_directory:   core/<stack> or compose/<stack>
file_paths:      ["docker-compose.yml", "docker-compose.override.yml"]
env_file_path:   .env
files_on_host:   false
```

`/opt/stacks/<stack>/.env` is generated by Komodo from the Stack Environment and
is never edited by hand. The Stack Environment is the source of truth.

Host-based stacks keep `files_on_host: true` and an absolute `run_directory`
under `/opt`.

### Private services with their own GitHub Actions

These services are not versioned in this repository. Their deployment workflows own
the code and, for RedAlchemy, the runtime.

| Service | Workflow | Runtime |
| --- | --- | --- |
| Portfolio | `RedRiotTank/Portfolio`, push to `main` | writes `dist/` to `/opt/portfolio/html` (symlink to `/opt/compose/portfolio/html`); `portfolio-web` is managed by Komodo host stack `portfolio` |
| PseudorandomometricSequencesApi | `RedRiotTank/PseudorandomometricSequencesApi`, push to `master` | builds the JAR and runs `docker-compose up -d` in `/opt/pseudorandomometricsequencesapi` (symlink to `/opt/compose/pseudorandomometricsequencesapi`); Komodo host stack `pseudorandomometricsequencesapi` |
| RedAlchemy Frontend | `RedRiotTank/RedAlchemyFrontend`, push to `main` | writes `dist/` to `/opt/redalchemy/frontend`; expects a host Nginx |
| RedAlchemy Backend | `RedRiotTank/RedAlchemyBackend`, push to `main` | clones to `/opt/redalchemy/backend`, runs `npm install`, and reloads PM2 process `redalchemy-backend` |

Do not move `/opt/portfolio`, `/opt/pseudorandomometricsequencesapi` or
`/opt/redalchemy` without updating those workflows. The first two are symlinks to
the normalized `/opt/compose` locations. RedAlchemy stays outside Komodo because
its workflows use PM2 and a host Nginx.

Known issues unrelated to Komodo normalization:

- The RedAlchemy frontend workflow runs `sudo systemctl reload nginx`, but this
  host has no `nginx.service`. The frontend files can be deployed, but the final
  reload step needs a host Nginx or a workflow change.
- The RedAlchemy backend defaults to `127.0.0.1:3000`, which is already used by
  Grafana's host port. The backend cannot bind until the port or Grafana's mapping
  changes.

## Rules

1. Never store data inside a Komodo clone. Clones are disposable.
2. Never edit a generated `.env`; edit the Komodo Stack Environment.
3. Keep overrides next to the base compose file and version them in Git.
4. Put host-specific persistent paths under `/opt/core` or `/opt/compose` and
   reference them with absolute paths from the Stack Environment.
5. `arr-stack`, `portfolio` and `pseudorandomometricsequencesapi` are the host-based
   stacks. Portfolio and pseudo are reached by their GitHub workflows through the
   `/opt/portfolio` and `/opt/pseudorandomometricsequencesapi` symlinks; update the
   workflow paths before moving either directory. RedAlchemy stays outside Komodo
   (`/opt/redalchemy`, PM2 + host Nginx + GitHub Actions).
6. `.env` files are generated by Komodo for Git stacks and mirrored by Komodo for
   host stacks. The only manual env outside that model is
   `/opt/redalchemy/backend/.env`, required by the PM2/GitHub backend workflow.
   Bootstrap envs (`/opt/core/komodo/.env` and the crimson periphery `.env`) are
   also manual by design.
